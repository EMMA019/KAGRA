# Asset ledger

The repo is public and its previews run on GitHub Pages, so every committed
asset must be allowed to be redistributed. `assets/LEDGER.json` records where
each asset came from and under which license. `CREDITS.md` is generated from it.

## What is built

| Piece | File | What it does |
|---|---|---|
| Ledger | `assets/LEDGER.json` | One entry per source pack. Covers every committed model, texture, audio file, font, map and clip. |
| Credits | `CREDITS.md` | Generated by `python3 tools/asset_ledger.py credits --write`. CI fails if it drifts. |
| License check | `tools/asset_ledger.py check` (also `tests/test_asset_ledger.py`, run by the CI pytest job) | Fails on an uncovered asset, a missing license, a non-redistributable asset in git, a CC-BY entry without attribution in `CREDITS.md`, or a `fetch_assets` manifest that disagrees with the ledger. |
| Import checks | `tools/import_asset.py` (tests in `tests/test_import_asset.py`) | Triangle count, texture size, file size, meshopt/Draco use, and a ledger-coverage gate for GLB, glTF and FBX. |

### Ledger fields

`id`, `name`, `source`, `author`, `url`, `license` (`cc0`, `cc-by`,
`standard-eula`, `restricted`, `custom`), `license_spdx`, `license_url`,
`license_evidence` (license files in the repo), `obtained`, `receipt_ref`
(an opaque id such as an order number, never a file), `attribution_required`,
`attribution_text`, `redistributable_in_public_repo`, `allowed_uses`, `paths`
(globs), `credits` (per-asset authors), `verified` (`checked` or
`owner_confirmation_needed`), `verified_how`, `notes`.

Rules the check enforces:

- Every tracked file with an asset extension (outside `docs/` and `tests/`) matches the `paths` of an entry.
- `redistributable_in_public_repo: false` means every path is under `assets-private/`, and no tracked file may match it.
- `standard-eula` and `restricted` can never be public-redistributable.
- `cc-by` needs `attribution_required: true` and its text in `CREDITS.md`.
- Nothing under `assets-private/` may be tracked. The directory is gitignored.
- `receipt_ref` must not look like a file path. No receipts go in the repo.

### Adding an asset

1. Check the license on the source page and keep the license file next to it.
2. Add a ledger entry, then run `python3 tools/asset_ledger.py credits --write`.
3. Run `python3 tools/import_asset.py path/to/model.glb --profile prop` (profiles: `prop`, `character`, `environment`, `default`).
4. `python3 tools/asset_ledger.py check` must report 0 errors.

Entries marked `owner_confirmation_needed` pass CI with a warning. List them with
`python3 tools/asset_ledger.py unverified`.

## Import limits

| Profile | Triangles | Largest texture | File |
|---|---|---|---|
| prop | 20,000 | 1024 px | 4 MB |
| character | 60,000 | 2048 px | 12 MB |
| environment | 150,000 | 2048 px | 20 MB |
| default | 100,000 | 2048 px | 8 MB |

Triangles are counted as the scene instances them. Geometry over 512 KiB without
meshopt gets a warning. A file that *requires* meshopt, Draco or Basis is an
error, because `kagra-shared` does not decode them yet. FBX is read as binary
FBX 7.x for polygon counts only; the engine loads glTF/GLB, so FBX must be
converted before runtime use.

## Not built yet: private assets (design only)

Paid or restricted assets (Unity Asset Store, Fab, itch.io paid, Mixamo files,
Quaternius packs downloaded under the 2026-08-28 Asset License) must never be
in this public repo. The design below is for the owner to choose from. Nothing
here creates an account, a repo, a bucket or a purchase.

Common shape: the ledger entry keeps `redistributable_in_public_repo: false`
with `paths` under `assets-private/<pack>/`. A fetch script
(`tools/fetch_private_assets.py`) would download into that gitignored folder
and verify a checksum recorded in the ledger. Public CI and the Pages preview
build without the files, using the placeholder models already in `assets/`.
The ledger check still passes because it only needs the entries, not the files.

| Option | How | Cost | Risk |
|---|---|---|---|
| A. Private GitHub repo or release | A private repo `kagra-assets-private`; fetch with a read-only token from an env var or CI secret. | Free on the current plan. | The token must not leak into logs; forks cannot fetch. |
| B. Private bucket | A private S3 or R2 bucket with a read-only key. | Small monthly cost. | New account and key to manage. |
| C. Local folder only | Each machine keeps its own `assets-private/`; a manifest lists names and SHA-256. | None. | No shared source of truth; builds that need the files only run on that machine. |

Recommendation: A for a small team, because it reuses the existing GitHub
login and keeps the checksum in the ledger. Whatever the choice, shipped
builds (APK, Windows zip) may include paid assets only if the license allows
redistribution inside a game, and that is recorded per entry in `allowed_uses`.
