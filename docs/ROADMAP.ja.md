## 最終目標（北極星）

**「Python で AI に体を与えるなら KAGRA」という第一想起。**
JS における three-vrm のポジションの Python 版。

これはエンジンの機能数ではない。測るのは Pull:

- 投稿していない日に install と「動いた」報告が来るか（オーガニック比率）
- 外部発のコンテンツ（記事・動画・配信）が毎月出るか

売るのは完成品（アバターがいる、AI が配信する）。ライブラリの需要はその裏から流れる。
Web で three-vrm と戦わない。pygame の土俵にも上がらない。

到達の形は Stage 2〜5（コード不要の完成品 → 旗艦の公開運用 → 他の需要に体を刺す → 複利）。
Stage 1 の楔は、どの完成品が本物の痛みかを数字で選ぶためにある。

**エンジンの到達点は 80% である。** 北極星の代わりではない。80% は「Python で同等のものが書ける」。第一想起は外から観測できる Pull。

## エンジン 80%（何が 100% で、今何% か）

100% = デスクトップ Python で three-vrm + three.js + Ursina を置き換えて、仕事の種類が足りないと感じない。
three.js のモジュール全部・WebXR・映画のポストスタックは 100% に入れない。
80% は「普段の仕事が通る」。100% は「three.js のリポジトリを Python に移植した」。

重み（合計 100）: 体 30 / 絵 45 / 書き味 20 / 世界 5。頭脳の HTTP 面は楔 A/B で、この % には薄い。

| 領域 | 今 | 80% で必要 | 100%（今はやらない） |
|---|---|---|---|
| 体 three-vrm | **約 80%** | 維持。2 体の計測と手レイヤがあれば 85 | Web/XR、ブラウザ three-vrm 対決 |

## 4 原則

1. **需要は完成品から逆流する。** 「エンジンが欲しい」ではない。
   「デスクトップに自分のアバターがいる」「寝てる間に AI が配信してる」が欲しい。
2. **Push は検証手段であって需要ではない。** 投稿した日の star は反応。
   投稿していない日の流入が需要。
3. **楔は同時に打ち、勝者を数字で選ぶ。** 同じ労力で最大 4 本。
   D を箱部屋の初日品質で投げない（「作るものがしょぼい」と読まれる）。
4. **80% に必要なものを足す。楔が詰まっているものから。**
   棚の 2D / エディタ / tilemap は Front に戻さない（製品の決めごと）。
   頭脳は楔 A/B が詰まっているので面を先に置いた。絵の画素は楔 D と 80% の本体。
   SSAO や OSM を先にマージして室内影を飛ばさない。

## 何で戦うか

技術的な優位は「点」ではなく「縦の貫通」。

1. **統合密度 × 配布**: 依存ゼロ・約 5MB wheel で、glTF → MToon → SpringBone →
   リップシンク → TTS → OBS 仮想カメラが 1 プロセス。競合はだいたいブラウザ / Godot に描画を投げている
2. **VRM 実装深度**: マルチスキン、コライダー付き SpringBone、node constraint、
   expression override、一人称レイヤー
3. **エージェント開発ループ**: `kagra.verify` / golden / `docs/API_INDEX.md` / MCP。
   ループがあっても、出せるゲームが初日ならエージェントは来ない

## 製品の決めごと（ここは変えない）

- 汎用 2D エンジンとして pygame / pyxel の土俵で競わない
- 2D の `Entity` / tilemap / Tk エディタ / boids を Front に戻さない

- Web レンダラで three-vrm と直接対決しない（ブラウザデモは Stage 5 の裾野）

- text-to-vrma / Irodori-TTS のベンダリング（レシピで繋ぐ）
- YouTube / Twitch の API キーをコアやログに置くこと
- 比較表で競合を貶すこと
- デモへの高解像度テクスチャ / アセット同梱（プロシージャル + ライト）
- `KAGRA_ENGINE_GUIDE.md` を現行仕様として増やす（履歴は `docs/archive/`。現行は README と API 索引）
- 箱部屋 4 本目を D-6 と呼ぶこと
- Windows は EventLoop 1 本。GPU は `kagra.verify` の subprocess
